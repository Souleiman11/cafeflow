### Important distinction

**SUPER\_ADMIN**\= administers the CaféFlow SaaS.

**OWNER**\= owns the café business inside CaféFlow.

**MANAGER**\= operates the café.

They are deliberately separate.

3\. ACTORS
==========

3.1 Super Admin
---------------

Platform-level role.

Responsibilities:

*   platform administration
    
*   tenant administration
    
*   subscription/platform administration
    
*   support
    
*   system monitoring
    
*   platform configuration
    
*   suspend/reactivate tenants
    
*   manage platform administrators
    

Should not normally:

*   manage café tables
    
*   create customer orders
    
*   manage waiter workflow
    
*   edit café menus
    
*   operate a café

5\. MANAGER
===========

Operational administrator.

Can:

*   manage tables
    
*   manage menu
    
*   manage employees
    
*   manage waiter/barista accounts
    
*   manage active sessions
    
*   manage orders
    
*   handle customer requests
    
*   view dashboard
    
*   view analytics
    
*   use AI assistant
    
*   view operational history
    

Cannot:

*   manage CaféFlow platform
    
*   access another tenant
    
*   create SUPER\_ADMIN
    
*   transfer platform ownership
    

6\. WAITER
==========

Operational front-of-house employee.

Can:

*   see tables
    
*   open sessions
    
*   monitor sessions
    
*   confirm orders
    
*   mark orders served
    
*   move sessions
    
*   merge/split table sessions
    
*   handle assistance requests
    
*   handle table-change requests
    
*   initiate/record payment according to configured workflow
    

Cannot:

*   manage employees
    
*   modify menu
    
*   access business administration
    
*   use manager AI analytics
    
*   access another café
    

7\. BARISTA / CHEF
==================

Preparation employee.

Can:

*   see preparation queue
    
*   view order items
    
*   see notes/customizations
    
*   start preparation
    
*   mark items/order ready
    
*   report preparation problems
    

Cannot:

*   manage employees
    
*   manage tables
    
*   modify café configuration
    
*   access financial analytics

*   orders
    
*   payment
    
*   operational state
    

This distinction is important.

125\. BUSINESS RULES
====================

### Tenant

1.  Every café belongs to exactly one tenant.
    
2.  Tenant data cannot be accessed across tenants.
    
3.  A tenant has at least one owner.
    
4.  Tenant cannot be operational without an active owner.
    
5.  Suspended tenant users cannot perform normal café operations.
    

126\. OWNER RULES
=================

1.  Owner belongs to one or more authorized café tenants depending on future architecture.
    
2.  Owner cannot create SUPER\_ADMIN.
    
3.  Owner can invite managers.
    
4.  Owner can invite operational employees.
    
5.  Owner can deactivate employees.
    
6.  Ownership changes must be audited.
    

127\. MANAGER RULES
===================

1.  Manager belongs to a tenant.
    
2.  Manager cannot access other tenants.
    
3.  Manager can manage operational resources.
    
4.  Manager cannot manage platform configuration.
    
5.  Manager cannot create SUPER\_ADMIN.
    

128\. ORDER RULES
=================

1.  Every order belongs to exactly one table session.
    
2.  Every order belongs to exactly one tenant.
    
3.  An order cannot move between tenants.
    
4.  Product price is snapshotted.
    
5.  Invalid state transitions are rejected.
    
6.  Paid orders cannot be casually modified.
    
7.  Cancellation is state-controlled.
    
8.  Every important transition is auditable.
    

129\. SESSION RULES
===================

1.  A session belongs to one tenant.
    
2.  A session may contain multiple tables.
    
3.  A session may contain multiple orders.
    
4.  Moving a table does not recreate orders.
